## 一、三层模型（0.2.1）

```
工作区 ──git add──► 暂存区 ──git commit──► 版本库(.git)
   ▲                                          │
   └────────── git restore ───────────────────┘
```

| 区域 | 装什么 |
|---|---|
| 工作区 | 你正在编辑的**当前内容** |
| 暂存区（index） | **下次提交要包含哪些改动**的清单 |
| 版本库 | 已提交的**历史快照** |

- **暂存区为什么存在**：让「提交」从"打包整个目录"变成"挑选一组逻辑相关的改动"——这是 git 区别于"复制备份"的根本
- **`add` 是拍快照，不是登记文件**：add 之后又改文件，暂存区里还是**add 那一刻**的内容
- **`commit` 只搬运暂存区 → 版本库，不碰工作区**（所以 commit 后 `cat` 还是最新内容）
- 想看历史里的版本：`git show HEAD:file`
- **`git status --short` 两位字符**：`M `/` M`/`MM`/`??`——`MM` = add 之后又改了

## 二、数据模型（0.2.2）

**git 存快照，不存 diff**；靠「内容寻址 + 相同内容只存一份」避免膨胀。

```
commit 对象  →  tree（目录清单：文件名 → blob 哈希）  →  blob（文件内容）
                └── parent：指向父 commit（历史链）
```

- blob 的名字 = **内容**的哈希 → 两个不同文件名但内容相同 → **同一个 blob**（可验证：`git rev-parse HEAD:x.txt HEAD:y.txt`）
- **`git diff` 是现算的**，存储里没有 diff（tree 里只有 blob 引用）
- git 只记录权限中的**可执行位**（644 / 755），**不记录属主、属组**（那属于部署环境）

## 三、分支（0.2.3）

**分支 = 一个 41 字节的文件，内容是一行 commit 哈希。**

```
HEAD（内容 "ref: refs/heads/master"）→ refs/heads/master（一行哈希）→ commit
```

- 创建分支 = 复制一个小文件（对比 SVN 复制整棵目录树）→ **"零成本"的字面含义**
- **提交时被改写的是「当前分支文件」，HEAD 不动**

| 合并场景 | 结果 | 历史形状 |
|---|---|---|
| master 未动 | **Fast-forward**：只挪指针，无新 commit | 一条直线 |
| 两边各有新提交 | **三方合并**：新 commit 有**两个 parent** | 分叉再汇合 |

- **detached HEAD**：`git switch --detach <hash>`（`switch` 拒绝裸 commit，必须显式声明）
  - 铁证：`cat .git/HEAD` 变成**裸哈希**；`git log` 标签从 `(HEAD -> master)` 变成 `(HEAD)`，**箭头消失**
  - 风险：此处提交不属于任何分支，切走后成孤儿
- **工作区的改动不属于任何分支**——它会跟着你切分支来回走。所以「切分支前先 `git status`」

## 四、远程（0.2.4）

**远程只是「一个名字 + 一个 URL」，git 不关心它是 GitHub 还是本地目录。**

- 裸仓库（`git init --bare`）**没有工作区**——只被 push/pull，不给人编辑
- `origin` 只是 `clone` 自动起的**默认名字**
- `-u`（`--set-upstream`）建立追踪关系，之后 `git push` / `git pull` 免参数

### 🔑 `origin/master` 是**本地文件**，是缓存

- 位置：`.git/refs/remotes/origin/master`
- 含义：「**上次与远程通信时**，远程 master 指向哪个 commit」→ **可能过时**

```
push 成功后：  Your branch is up to date with 'origin/master'    ← 但远程早已更新
git fetch 后： Your branch is behind 'origin/master' by 1 commit ← 才同步下来
```

### `fetch` vs `pull`

```
git fetch  →  ... master -> origin/master      ← 只更新本地缓存，不碰工作区
git pull   →  Updating ... Fast-forward        ← 额外把改动展开到工作区
```

- **fetch 动的是数据库，pull 额外动了你的文件**
- fetch 后 `git log` 看不到远程新提交，`git log --all` 能看到

## 五、撤销（0.2.5）

| 想撤销什么 | 命令 | 可恢复性 |
|---|---|---|
| 工作区改动（未 add） | `git restore <file>` | 💀 **永久消失** |
| 暂存区登记（已 add） | `git restore --staged <file>` | 🟢 工作区不动 |
| 本地 commit（未推） | `git reset [--soft\|--mixed\|--hard] HEAD~n` | 见下 |
| **已推送**的 commit | `git revert <commit>` | 🟢 不改历史 |

| 模式 | 分支指针 | 暂存区 | 工作区 | 改动去了哪 |
|---|---|---|---|---|
| `--soft` | 后移 | 不动 | 不动 | 回到**暂存区** |
| `--mixed`（默认） | 后移 | 重置 | 不动 | 回到**工作区** |
| `--hard` | 后移 | 重置 | 重置 | 💀 **消失** |

- **reset vs revert 的判据只有一条：这个 commit 推了没有**
  - 没推 → `reset`（改写历史，干净）
  - 推了 → **必须 `revert`**（追加反向 commit，原 commit 保留 → 有审计线索）
- **黄金法则：不要 reset / 强推已共享的 commit**（否则所有拉过的人一起错乱）
- **`git reflog` 是安全网**：能救回被 reset 掉的 **commit**
- ⚠️ **但只有「曾被 commit 引用」的内容能恢复**。`restore` 丢的工作区改动、从未 commit 的改动，**谁也救不了**
- **自保策略：舍不得的改动，先 `git commit`（不是先 `git add`）**

## 六、命令速查

| 目的 | 命令 |
|---|---|
| 看状态 / 简洁状态 | `git status` / `git status --short` |
| 看未暂存 / 已暂存的差异 | `git diff` / `git diff --staged` |
| 挑选文件提交 | `git add <file...>`（❌ 别用 `git add .`） |
| 提交 | `git commit -m "类型(范围): 描述"` |
| 看历史 / 图形 | `git log --oneline` / `git log --oneline --graph --all` |
| 看某版本的文件 | `git show HEAD:path/to/file` |
| 看对象内部 | `git cat-file -p HEAD^{tree}` |
| 分支 | `git branch` / `git switch <b>` / `git switch -c <b>` |
| 合并 | `git merge <b>`（带 `-m` 避免弹编辑器） |
| 远程 | `git remote -v` / `git push -u origin master` / `git fetch` / `git pull` |
| 撤销 | 见第五节 |
| 救回 commit | `git reflog` → `git reset --hard HEAD@{n}` |
| 暂存草稿 | `git stash` / `git stash list` / `git stash pop` |

## 七、危险操作清单（动手前先想 3 秒）

| 命令 | 危险点 |
|---|---|
| `git restore <file>` | 💀 丢弃的改动**永久消失**（先 commit！） |
| `git reset --hard` | 💀 未 commit 的改动丢失；已 commit 的可靠 reflog 找回 |
| `git push --force` | 💀 改写远程历史，会坑到所有协作者（已共享的 commit 用 `revert`） |
| `git add .` | ⚠️ 可能把临时文件/密钥/大文件带进提交 |
| `git checkout <file>` | ⚠️ 静默丢弃文件改动 → 用 `git restore` 替代 |
| `git commit`（无 `-m`） | ⚠️ 会打开编辑器（vim 不熟时用 `-m`） |

## 八、提交规范（本项目约定）

```
<类型>(<范围>): <描述>
 类型：feat | fix | docs | refactor | test | chore
 范围：drv | app | esp32 | ai | proto | skill | stage0
```

- 一个 commit = **一件可解释的事**（如果 message 写不顺，通常说明分组错了，该拆）
- **commit 前先 `git diff --staged`** —— 最后一道防线
- `commit ≠ 备份`：本地库"完整"不等于"安全"，**同一份历史要存在两个物理位置**
